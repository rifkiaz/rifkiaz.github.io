        apa itu GitOps dan Argo CD?
        • GitOps artinya Git jadi satu-satunya sumber kebenaran. Mau ganti apa pun di cluster, caranya lewat commit, bukan kubectl manual.
        • Argo CD jalan di dalam cluster dan menarik (pull) manifest dari Git, lalu membandingkannya dengan isi cluster. Cluster ga perlu dibukakan akses dari luar buat deploy.
        • Sync status menjawab "isi cluster sama dengan Git atau ngga" (Synced / OutOfSync). Health menjawab "aplikasinya sehat atau ngga" (Healthy / Progressing / Degraded). Keduanya beda: bisa Synced tapi Degraded.
        • Polling: aslinya Argo CD cek Git tiap 3 menit (atau langsung kalau pakai webhook). Di sini dipercepat jadi 10 detik, dan kamu bisa klik refresh.
        • Auto-sync otomatis menerapkan commit baru. Self-heal mengembalikan perubahan manual di cluster ke kondisi Git. Tanpa self-heal, drift dibiarkan dan cuma ditandai OutOfSync.
        • Rollback di Argo CD mengembalikan cluster ke revisi lama, tapi Git tetap di commit terbaru. Karena itu rollback cuma bisa saat auto-sync mati. Cara yang lebih GitOps adalah git revert.
        • Rolling update di sini pakai maxSurge: 1 dan maxUnavailable: 0: pod lama baru dimatikan setelah pod baru siap. Makanya image yang rusak ga bikin aplikasi mati, cuma rollout-nya macet.

        Ini simulasi, bukan Argo CD beneran, dan waktunya dipercepat. Semua cuma ada di browser kamu dan ga disimpan di mana pun. Refresh halaman buat mulai dari awal.
